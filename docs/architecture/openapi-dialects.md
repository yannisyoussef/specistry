# OpenAPI 3.0 and 3.1 dialect map

SPEC-003 made this map executable: every row below is proven by adapter tests over paired fixtures (`tests/fixtures/openapi/pairs`, `basic-3.0.yaml`, `basic-3.1.yaml`, `openapi-3.0.yaml`, `polymorphism.yaml`, `recursive.yaml`), the inline cases in `packages/openapi/src/pipeline.test.ts`, and the table-driven support-matrix rows in `packages/openapi/src/dialect-matrix.test.ts`, which assert exact diagnostics per dialect for the constructs named in the [support matrix](../openapi.md#support-matrix). Matrix rows that are documented but not yet covered by a dedicated test are listed as tracked items in the [SPEC-003 review record](../reviews/spec-003.md). The complete per-construct disposition table lives in the [OpenAPI ingestion reference](../openapi.md#support-matrix).

| Concern                 | OpenAPI 3.0                                         | OpenAPI 3.1 / JSON Schema 2020-12                   | Canonical rule (proven)                                                                                                                                                                                          |
| ----------------------- | --------------------------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Nullability             | `nullable: true` modifies a typed schema            | `null` participates in `type` arrays or applicators | Both project to byte-identical `anyOf [typed, null]`, constraints included; absence is never nullable; `nullable` in 3.1 is an unsupported keyword                                                               |
| Boolean schema          | Not supported as a Schema Object                    | `true` and `false` schemas                          | 3.1 keeps `boolean-schema` nodes; 3.0 boolean schemas are invalid                                                                                                                                                |
| Exclusive bounds        | Boolean flag paired with minimum/maximum            | Numeric `exclusiveMinimum`/`exclusiveMaximum`       | 3.0 pairs convert to numeric exclusive bounds; a flag without its bound, or a 3.1 boolean, is invalid                                                                                                            |
| `$ref` siblings         | Reference Object siblings generally ignored         | Schema `$ref` siblings are evaluated                | 3.0 siblings become one ignored-annotation diagnostic per key (`x-*` exempt); 3.1 schema annotations attach to the ref, other keywords `allOf`; 3.1 Reference Object `summary`/`description` override the target |
| Tuples                  | Array `items` patterns are limited/dialect-specific | `prefixItems` plus `items`                          | 3.1 `prefixItems` becomes a `tuple` with `additionalItems` from `items`; 3.0 `prefixItems` is an unsupported-semantic warning and 3.0 array-form `items` is invalid                                              |
| Type arrays             | Not supported                                       | Multiple types are allowed                          | 3.1 arrays project to `anyOf` of typed variants with `enum`/`const` distributed and keywords reported only when no declared type uses them; empty arrays and 3.0 arrays are invalid                              |
| `const`                 | Not supported directly                              | Any JSON value                                      | 3.1 preserves any finite JSON value; 3.0 `const` is an unsupported-semantic warning                                                                                                                              |
| `enum`                  | Values constrained by 3.0 schema vocabulary         | Any JSON values under JSON Schema                   | Values and order preserved; duplicates or non-finite numbers are invalid                                                                                                                                         |
| Keywords without `type` | Schema subset often interpreted structurally        | Assertions/applicators do not imply instance type   | `type-less` node with applicable constraint groups; no keywords at all becomes `any`                                                                                                                             |
| Schema dialect          | Fixed OpenAPI schema dialect                        | `jsonSchemaDialect` and per-schema dialect behavior | Root `openapi` version selects the dialect; a non-default `jsonSchemaDialect` warns and is read as 2020-12                                                                                                       |
| `examples`              | Schema `example` plus media examples                | JSON Schema `examples` plus OpenAPI examples        | `example` and 3.1 `examples` become bounded JSON examples; 3.0 `examples` is an ignored annotation                                                                                                               |
| Body encodings          | Multipart/form Encoding Objects                     | Multipart/form Encoding Objects                     | Per-property content type (with multipart headers) or serialization mode; unknown properties are invalid                                                                                                         |
| Webhooks/callbacks      | Callbacks supported                                 | Callbacks plus top-level webhooks                   | Unsupported-semantic warnings at `/webhooks`, `/callbacks`, and response `links`                                                                                                                                 |

The resolver distinguishes Schema Objects from Reference Objects, records a source location (document plus JSON pointer) for every diagnostic, handles local cycles through registry identities derived from source path plus pointer, and never retrieves a remote reference merely because parsing found its URL.

The canonical decisions above are frozen by SPEC-001. SPEC-003 proved each mapping against paired dialect fixtures without changing model semantics; unsupported vocabulary is diagnosed, never coerced.
